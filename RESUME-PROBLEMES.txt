───────────────────────────────────────────────────────────────
🔴 PROBLÈME CRITIQUE #1 - BUG "AUTRE" MARQUE
───────────────────────────────────────────────────────────────

Quoi: Quand tu sélectionnes "Autre" dans les marques, un champ
      apparaît pour taper la marque. MAIS les deux champs ont
      le MÊME nom "marque" et se battent entre eux!

Ligne: 229-237

Symptômes:
❌ Tu tapes "Ferrari" → le dropdown se réinitialise
❌ La valeur finale envoyée est incorrecte
❌ Expérience utilisateur cassée

Solution rapide:
→ Renommer le champ en "marque_autre"
→ Fusionner les deux valeurs dans onSubmit

Impact: 🔴 CRITIQUE - Le formulaire est CASSÉ si "Autre" choisi

───────────────────────────────────────────────────────────────
🟠 PROBLÈME #2 - ANNÉE HARDCODÉE 2025
───────────────────────────────────────────────────────────────

Quoi: L'année est écrite en dur "2025" au lieu d'utiliser
      l'année actuelle (2026)

Ligne: 205

Code actuel:
Array.from({ length: 30 }, (_, i) => 2025 - i)
                                      ^^^^

Symptômes:
❌ Les voitures 2026 ne sont pas dans la liste
❌ En 2027, la liste sera encore plus obsolète

Solution:
Array.from({ length: 30 }, (_, i) => new Date().getFullYear() - i)

Impact: 🟠 IMPORTANT - Liste obsolète

───────────────────────────────────────────────────────────────
🟠 PROBLÈME #3 - EMAIL SANS VALIDATION
───────────────────────────────────────────────────────────────

Quoi: Le champ email n'a AUCUNE validation de format

Ligne: 179

Code actuel:
{...register("client_email")} ← Pas de validation!

Symptômes:
❌ Tu peux entrer "abc" et ça passe
❌ L'email sera invalide
❌ Les notifications email échoueront
❌ Pas de message d'erreur pour l'utilisateur

Solution:
{...register("client_email", {
  pattern: {
    value: /^[^\s@]+@[^\s@]+\.[^\s@]+$/,
    message: "Format d'email invalide"
  }
})}

Impact: 🟠 IMPORTANT - Données invalides acceptées
